# Размещение на tripo3d.lens4web.com с nginx

Сайт открыт для всех. Каждый пользователь вводит собственный API-ключ. Ключ хранится только в памяти Node.js-сервера; в браузере остаётся защищённая cookie со случайным идентификатором сессии.

Приложению нужен работающий Node.js-процесс. Одной загрузки HTML в папку поддомена недостаточно. nginx принимает HTTPS-запросы и передаёт их на `127.0.0.1:3000`.

## 1. Разместите файлы и установите зависимости

Установите Node.js 24 LTS. Распакуйте архив в `/opt/tripo3d`, включая папки `deploy`, `assets`, `scripts` и скрытый файл `.env.example`. В архиве нет ключей, `node_modules` или посторонних данных сессий.

```sh
sudo useradd --system --home-dir /opt/tripo3d --shell /usr/sbin/nologin tripo3d
cd /opt/tripo3d
npm ci --omit=dev
sudo chown -R root:tripo3d /opt/tripo3d
sudo chmod -R g+rX,o-rwx /opt/tripo3d
```

Если пользователь уже существует, повторять `useradd` не нужно. Установка Pillow на сервер не требуется: иконки и превью уже готовы.

## 2. Настройки службы

```sh
sudo cp /opt/tripo3d/.env.example /etc/tripo3d.env
sudo chmod 600 /etc/tripo3d.env
```

Файл уже настроен на ваш поддомен:

```ini
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
PUBLIC_ORIGIN=https://tripo3d.lens4web.com
```

API-ключи в этот файл добавлять не нужно. Если порт 3000 занят, поменяйте `PORT` и `proxy_pass` в nginx на один и тот же свободный порт.

В `deploy/tripo3d.service` проверьте путь `/usr/bin/node` командой `command -v node`; при необходимости замените `ExecStart`. Node не должен находиться в домашней папке пользователя, к которой служба ограничивает доступ.

```sh
sudo cp /opt/tripo3d/deploy/tripo3d.service /etc/systemd/system/tripo3d.service
sudo systemctl daemon-reload
sudo systemctl enable --now tripo3d
curl -fsS http://127.0.0.1:3000/healthz
```

Ожидается `{"status":"ok"}`. Используйте один процесс Node: серверные сессии хранятся в памяти и не синхронизируются между процессами.

## 3. nginx, DNS и сертификат

DNS `tripo3d.lens4web.com` должен указывать на ваш сервер. Используйте существующий сертификат для этого поддомена или выпустите его привычным для сервера способом.

В `deploy/nginx.conf` уже указан ваш домен; проверьте пути `ssl_certificate` и `ssl_certificate_key`. Пароль на сайт не требуется. nginx должен передавать cookie серверной сессии: не добавляйте `proxy_set_header Cookie ""`.

Для типичного Debian/Ubuntu:

```sh
sudo cp /opt/tripo3d/deploy/nginx.conf /etc/nginx/sites-available/tripo3d
sudoedit /etc/nginx/sites-available/tripo3d
sudo ln -s /etc/nginx/sites-available/tripo3d /etc/nginx/sites-enabled/tripo3d
sudo nginx -t
sudo systemctl reload nginx
```

Если старый сайт уже подключён через символьную ссылку, повторно создавать её не нужно. Если вы использовали предыдущий шаблон с `auth_basic`, замените его новым файлом: иначе поисковики и пользователи по-прежнему увидят запрос пароля.

Для панели хостинга добавьте эквивалентные настройки через неё, чтобы не создавать второй конфликтующий `server` для того же домена. `limit_req_zone` располагается внутри общего контекста `http`, не внутри `server`.

Не открывайте порт Node наружу. Серверу нужен исходящий HTTPS-доступ к Tripo API и хранилищу файлов.

## 4. Проверка после размещения

Откройте https://tripo3d.lens4web.com. Страница, языковые версии, иконки, `robots.txt`, `sitemap.xml` и социальное превью доступны без пароля. Для API и скачивания необходим применённый ключ в серверной сессии. Применение ключа не проверяет его действительность: неверный ключ вызовет ошибку при запросе к Tripo.

По умолчанию язык выбирается из настроек браузера, тема — из настроек системы. Ручной выбор сохраняется. API-ключ удаляется при отключении, после часа бездействия, через четыре часа с начала сессии или при перезапуске сервера.

Отправьте `https://tripo3d.lens4web.com/sitemap.xml` в Google Search Console после публикации, если у вас настроен доступ к домену. Метаданные помогают прочитать сайт и показать превью; они не гарантируют индексацию или позицию в поиске.

Диагностика:

```sh
sudo systemctl status tripo3d
sudo journalctl -u tripo3d -n 50 --no-pager
sudo nginx -t
```

На локальном Mac проверены интерфейс и меры защиты. Проверки сертификата, nginx, службы systemd и реального публичного домена выполняются на вашем сервере. Развёртывание на сервере не выполнялось.

Для обновления остановите службу, замените файлы, выполните `npm ci --omit=dev`, восстановите права как в первом шаге и запустите службу. Перезапуск удалит активные ключи; пользователям потребуется применить их повторно.
